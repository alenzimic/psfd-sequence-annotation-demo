# Hosting Strategy for PSFD Sequence Annotation Demo

## The Goal
To make the PSFD Sequence Annotation UI and its backend API publicly accessible for other scientists, without incurring expensive commercial cloud computing costs (e.g., AWS, Google Cloud).

## The Challenge
The backend API relies on heavy computational tools:
1. **MMseqs2** for sequence alignment (requires significant CPU and memory).
2. **ESMC (PyTorch)** for embeddings (benefits from GPUs or high-end CPUs).
Hosting these on commercial cloud platforms is prohibitively expensive. However, we already have access to massive, "free" compute power via the university's BioHPC cluster.

## Proposed "Hybrid" Architecture

We can achieve a production-grade deployment using existing free/institutional resources by splitting the frontend and backend:

### 1. Frontend: GitHub Pages (Free & Public)
*   **What it does:** Hosts the static UI (HTML, CSS, JS).
*   **Benefits:** It is completely free, highly reliable, and automatically provides a public HTTPS domain (e.g., `https://alenzimic.github.io/...`). 
*   **Action Required:** Push the UI code to a GitHub repository and enable GitHub Pages. No server maintenance required.

### 2. Backend: Cornell BioHPC (Free Compute)
*   **What it does:** Runs the FastAPI server (`api_server.py`), MMseqs2 databases, and ESMC models.
*   **Benefits:** Leverages the university's massive compute infrastructure for heavy sequence analysis at zero additional cost.
*   **Action Required:** Keep the FastAPI server running persistently on a BioHPC node (e.g., using `systemd`, `tmux`, or `supervisor`).

### 3. The Bridge: BioHPC Web Gateway
Currently, the UI is hardcoded to talk to `localhost:8899`, which only works when a developer has an active SSH tunnel open. For the public to use it, the GitHub Pages UI needs a public URL to talk to.

Instead of renting a dedicated web server (like the Apache/Rocky Linux setup used by tools.moghelab.org), we can use the BioHPC's built-in web proxy services. 

**Steps to connect them:**
1.  **Contact BioHPC IT:** Request that they expose our internal FastAPI port (8899) through their reverse proxy.
    *   *Example Request:* "We have a web API running on port 8899 on our node. Can you expose this via the institutional proxy to a public HTTPS URL (e.g., `https://psmm-api.biohpc.cornell.edu`)?"
2.  **Enable CORS:** Update the FastAPI script to include a CORS middleware policy that explicitly allows requests coming from the `alenzimic.github.io` domain.
3.  **Update the UI:** Change the `fetch()` calls in `app.js` to point to the new `biohpc.cornell.edu` URL instead of `localhost`.

## Conclusion
By hosting the UI on GitHub Pages and proxying the BioHPC node to the public web, we get a secure, HTTPS-enabled, publicly accessible tool powered by supercomputer-level hardware—all while entirely avoiding commercial cloud hosting fees.
